# CookMyFridge 完整方案

## 一、项目定位

CookMyFridge 是一个**数据集检索 + AI 创意双引擎**的料理筛选网站。

用户点选冰箱里的食材后：

1. **数据集负责靠谱**：筛出能做的菜、只差一点的菜、不同烹饪方式。
2. **AI 负责开脑洞**：数据集没有的组合，AI 给新菜；数据集有的菜，AI 给变体主意。
3. **静态网页负责好部署**：数据预构建，AI 结果预生成缓存，网页可托管在 GitHub Pages、Cloudflare Pages、Netlify 等。

一句话：

> **CookMyFridge = 菜谱数据集兜底 + AI 加料 + 静态网页部署。**

---

## 二、核心体验

### 1. 冰箱点选
首页展示食材墙：蔬菜、肉蛋、水产、主食、豆乳、调料、水果、冷冻食品。  
用户点“鸡蛋、番茄、土豆、午餐肉”，点击 **Cook My Fridge**。

### 2. 三条结果线
结果页分三栏或三个标签：

| 结果线 | 说明 |
|---|---|
| **Cook Now** | 现在就能做，缺失 0～1 样 |
| **Almost There** | 只差一点，缺 1～3 样，给替代方案 |
| **AI Wildcard** | 数据集没有的组合，AI 创意菜 |

### 3. 烹饪方式筛选
炒、煮、蒸、烤、煎、炸、炖、凉拌、微波炉、电饭煲、空气炸锅、免开火。

### 4. 菜谱详情页的 AI 加料
每个数据集菜谱详情页提供按钮：

- 换掉我没有的食材
- 给我懒人版
- 给我低卡版
- 换一种烹饪方式
- 用空气炸锅怎么做
- 剩菜怎么改造
- 融合一个别的菜系
- 给我三个数据集里没有的主意

这实现：**数据集有的，也让 AI 给出没有的主意。**

### 5. 冰箱盲盒
随机抽 3～5 种食材，AI 给一道“今日盲盒菜”，适合分享传播。

### 6. 我的冰箱
用户点选食材存本地浏览器，下次打开还在；可生成分享卡片：“我的冰箱能开 12 局”。

## 三、页面结构

静态网页建议 6 个页面：

1. **首页 / CookMyFridge**
   - 食材点选墙
   - 搜索食材
   - 常用组合快捷入口
   - 随机开一局

2. **结果页**
   - Cook Now
   - Almost There
   - AI Wildcard
   - 烹饪方式、时间、难度筛选

3. **菜谱详情页**
   - 食材、用量、步骤、时间、难度、烹饪方式
   - 缺失食材替代
   - AI 加料按钮
   - 数据来源与许可证标识

4. **AI 创意菜页**
   - 标注“AI 创意，未经过人工实测”
   - 结构化展示食材、步骤、烹饪方式、风险提示
   - 用户反馈：靠谱 / 离谱

5. **我的冰箱**
   - 本地保存食材
   - 历史开饭记录
   - 分享卡片

6. **About / Data Sources**
   - 数据集来源、许可证
   - AI 使用说明
   - 过敏原与食品安全提示

## 四、数据方案

### 1. 数据集组合
优先组合：

- **中文主库**：下厨房食谱语料库，规模大，适合中文用户。
- **结构化补充**：Recipe Cleaned Dataset、FoodEarth、CRWB，用于食材分类、营养、烹饪动作关联。
- **规模补充**：RecipeNLG、Recipe1M+，扩充菜名、食材组合和步骤表达。
- **可选补充**：HowToCook，作为中文程序员菜谱补充。

### 2. 统一菜谱字段
每条菜谱至少包含：

- 菜名
- 食材列表与用量
- 标准化食材名
- 烹饪方式
- 菜系
- 时间
- 难度
- 厨具
- 步骤
- 标签：快手、低卡、下饭、剩菜改造等
- 来源与许可证
- 是否 AI 生成

### 3. 预构建静态索引
静态网页不扫全量数据，提前生成：

- 食材倒排索引：食材 → 菜谱 ID
- 烹饪方式索引
- 时间/难度索引
- 食材同义词表：番茄/西红柿、土豆/马铃薯
- 食材替代表：没有黄油用什么、没有蚝油用什么
- AI 创意卡片缓存

网页只加载索引和按需数据分片。

### 4. 数据清洗重点
- 食材名称归一化
- 用量结构化
- 步骤去重
- 许可证记录
- 过敏原标注
- 生食、未熟、油炸安全提示

## 五、AI 双引擎策略

### 引擎 A：数据集检索
负责“靠谱”：

- 按食材匹配度排序
- 缺失食材最少优先
- 烹饪方式筛选
- 替代食材推荐
- 相似菜推荐

排序建议：

1. 匹配食材数量
2. 缺失食材数量
3. 用户选择的烹饪方式
4. 时间/难度
5. 数据质量与来源可信度

### 引擎 B：AI 创意
负责“没有的主意”：

- 数据集无结果时生成新菜
- 数据集有结果时生成变体
- 生成替代食材方案
- 生成懒人版、低卡版、空气炸锅版
- 生成冰箱盲盒菜
- 生成分享卡片标题

### AI 输出结构化要求
AI 必须按固定字段输出：菜名、食材、用量、步骤、时间、难度、烹饪方式、替代食材、风险提示、创意说明。  
前端只展示通过字段校验的结果。

### AI 内容标识
所有 AI 生成内容必须标注：

> AI 创意菜，未经过人工实测。请确保食材新鲜、彻底加热，注意过敏原。

## 六、静态网页部署方案

### 推荐架构
- **前端**：静态站点，任意框架或纯 HTML/JS。
- **数据**：JSON/JSONL 分片 + 预构建索引。
- **托管**：GitHub Pages、Cloudflare Pages、Netlify、Vercel 静态托管。
- **AI 代理**：Cloudflare Workers 或 Vercel Functions。
- **存储**：用户冰箱用 localStorage；分享卡片用 URL 参数；不需要数据库。

### 两种运行模式
1. **默认静态模式**：使用提前批量生成的 AI 创意卡片、替代食材表、变体建议，全部存成静态 JSON。网页无需后端也能玩。
2. **增强模式**：部署轻量代理，前端调代理，API Key 放服务端；加限流、日志、内容过滤。

最推荐：

> **Cloudflare Pages 托管静态网页 + Cloudflare Workers 做 AI 代理 + 预生成 AI 卡片兜底。**

### 为什么适合静态
- 菜谱检索可以完全前端完成。
- AI 创意可以预生成。
- 分享卡片可以用 URL 参数生成。
- 用户冰箱存本地。
- 成本极低，加载快。

## 七、短期大量使用 AI 的正确方式

不要在线一次次聊天，做离线批处理：

1. 批量生成食材同义词和替代表。
2. 批量给菜谱打标签：快手、低卡、下饭、空气炸锅、免开火。
3. 批量生成每个菜谱的 3 个变体主意。
4. 批量生成常见食材组合的 AI 创意菜。
5. 批量生成“数据集没有”的组合菜，缓存成静态卡片。
6. 批量生成评测问题集：哪些组合该有结果、哪些该 AI 兜底。
7. 人工抽检 5%～10%，记录失败模式。

AI 用量大，但结果沉淀成静态资产，网页部署后不依赖实时调用也能跑。

第一版只做：

1. 首页食材点选。
2. 结果页 Cook Now / Almost There / AI Wildcard。

## 十、验收指标

- 输入 3～5 种常见食材，3 秒内出结果。
- Cook Now 中缺失食材为 0 的占比 ≥ 60%。
- 每个菜谱详情页至少有 3 个 AI 变体建议。
- AI 创意卡结构化合格率 ≥ 95%。
- 移动端可用，首屏加载快。
- 所有 AI 内容有标识，所有数据有来源。

## 十一、风险与规避

| 风险 | 规避 |
|---|---|
| AI 菜谱不安全 | 强制风险提示，禁止生食建议，油炸/高压锅加警告 |
| 数据集许可证 | 逐库记录许可证，About 页公示 |
| 纯静态暴露 Key | 前端不放 Key，用代理或预生成 |
| AI 幻觉食材 | 食材白名单和同义词校验 |
| 结果太多 | 默认每栏 6～9 个，按匹配度排序 |
| 中文数据质量参差 | 人工抽检 + 来源可信度加权 |
