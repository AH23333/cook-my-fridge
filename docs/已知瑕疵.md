# 已知瑕疵清单（2026-11-08 收尾）

逐项记录现象、影响、位置。判断为「不值得现在修」的挂着即可，别占工位；
修任何一项前先跑 `python tests/run_browser_stages.py` + `python -m pytest tests -q` 拿基线。

## 1. 同步合并时部分键写入失败不单独告警

- **现象**：`applySyncPayload` 逐键 `writeRaw`，写失败的键不进返回的 `keys`，也不单独提示；
  用户只看到「已同步 N 项」，不知道有哪几个键没进去。
- **影响**：仅在浏览器存储满/被禁用时出现；同步结果可能悄悄不完整。
- **位置**：`web/js/sync.js` `applySyncPayload`（约 340 行）。
- **建议**：返回值加 `failed` 列表，调用方 toast 明示；改 harness 补一条部分失败断言。

## 2. ICS 未做 75 字节折行

- **现象**：`weekToICS` 输出长行不折叠。
- **影响**：RFC 5545 里是 SHOULD 而非 MUST；主流日历（Apple/Google/Outlook）实测容忍长行。
  暂无任何客户端因此出错。
- **位置**：`web/js/planner.js` `weekToICS` / `icsEscape`。
- **建议**：若将来有客户端报错再补 folding；别 preemptively 加。

## 3. 冰箱页「库存台账 / 库存批次台账」标题重复

- **现象**：fridge.html 的区块标题与 inventory-ui 面板标题措辞几乎相同，视觉上是两层一样的标题。
- **影响**：纯措辞冗余，无功能问题。
- **位置**：`web/fridge.html:17`（外壳）与 `web/js/inventory-ui.js:60`（内壳）。
- **建议**：外壳改为更宽的「批次与库存」或内壳去掉重复标题，二选一。

## 4. `config.LEGACY_ENV_FILE` 仍指向外部机器路径

- **现象**：兜底 .env 路径是 `D:\Py\PyCharmProjects\Langchain\lc-course\.env`。
- **影响**：仅影响原开发机以外的环境且只在项目本地 .env 缺失时兜底；有测试覆盖。
- **位置**：`src/cookmyfridge/config.py:25`。
- **建议**：等原开发机把 key 挪到项目本地 `.env` 后，把 legacy 兜底整段删掉。

## 5. 烹饪计时器在后台 >5 分钟时最多晚一个节流周期

- **现象**：到期时刻制已保证不按拍数漂移，但 Chrome 对后台 >5min 的标签页强化节流到约 1 分钟一拍，
  响铃最多晚一拍。
- **影响**：仅当用户长时间切走浏览器且不在烹饪模式常亮（wake lock 生效时不会发生）。
- **位置**：`web/js/page-recipe.js` 烹饪模式计时器。
- **建议**：不值得修；真要修得用音频常驻或 SW 通知，复杂度不成比例。

## 6. stage30 曾两次 chip 点击超时后原样转绿

- **现象**：同一代码同一站点，两次失败（"performing click action" 卡 30s）后第三次原样通过。
- **影响**：无代码改动；判为机器瞬态抖动（探针在失败窗口内同路径即时通过）。
- **位置**：`tests/browser_stage30.py` 首页 chip 点击段。
- **建议**：留观察项；若再出现，先查同机是否有其他重活进程抢资源。

## 7. `.gitignore` 的 scratch 规则保留但要求用后即删

- **现象**：`_*.py/_*.txt/_*.png` 规则曾让根目录攒了 74 个调试残留（已清）。
- **影响**：规则本身有用（台架临时探针），但容易被当成垃圾桶。
- **位置**：`.gitignore` 15-19 行。
- **建议**：规则保留；以后探针用完立刻删，回归提交前 `git status` 确认根目录无 `_` 前缀文件。
