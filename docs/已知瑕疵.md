# 已知瑕疵清单（2026-11-08 收尾）

逐项记录现象、影响、位置。判断为「不值得现在修」的挂着即可，别占工位；
修任何一项前先跑 `python tests/run_browser_stages.py` + `python -m pytest tests -q` 拿基线。

## 1. 同步合并时部分键写入失败不单独告警 —— 已修（1e57f32）

- **现象**：`applySyncPayload` 逐键 `writeRaw`，写失败的键不进返回的 `keys`，也不单独提示。
- **修复**：返回值带 `failed` 列表；部分失败时三处调用方 toast「N 项成功，M 项写入失败」，
  全部失败抛存储原因。harness 137→140 项锁定。

## 2. ICS 未做 75 字节折行 —— 不修（理由在案）

- **现象**：`weekToICS` 输出长行不折叠。
- **不修的理由**：RFC 5545 里折行是 SHOULD 而非 MUST；Apple/Google/Outlook 日历实测
  都容忍长行，该文件由 Service Worker 以 `text/calendar` 提供、无任何客户端报错记录。
  修 folding 的收益为零，风险是把已验证的 ICS 格式改出新边界 bug。
- **位置**：`web/js/planner.js` `weekToICS` / `icsEscape`。
- **触发重估**：一旦任一主流日历客户端报解析问题，立刻补 folding。

## 3. 冰箱页「库存台账 / 库存批次台账」标题重复 —— 已修（f6ba7ba）

- **修复**：外壳对齐其他区块风格为「📦 库存台账」，内壳改「批次明细」。

## 4. `config.LEGACY_ENV_FILE` 仍指向外部机器路径 —— 已修（dcfd043）

- **修复**：ZHIPU 键已迁至项目本地 `.env`（gitignored），legacy 兜底整段删除；
  来源只剩 `COOKMYFRIDGE_ENV_FILE` 覆盖与项目 `.env`。

## 5. 烹饪计时器在后台 >5 分钟时最多晚一个节流周期 —— 不修（理由在案）

- **现象**：到期时刻制已保证不按拍数漂移，但 Chrome 对后台 >5min 的标签页强化节流到约 1 分钟一拍，
  响铃最多晚一拍。
- **不修的理由**：烹饪模式的唤醒锁让屏幕常亮，前台计时走 250ms 拍，真实下厨场景不受影响；
  用户切走浏览器已超过 5 分钟且恰好压中到期瞬间才出现，且误差上限约 1 分钟、方向只会晚不会早
  （不会提前把菜端下来）。要再准需要音频常驻或通知 API，复杂度与收益不成比例。
- **位置**：`web/js/page-recipe.js` 烹饪模式计时器。
- **触发重估**：若收到「后台计时严重不准」的真实用户反馈，再评估通知式提醒。

## 6. stage30 曾两次 chip 点击超时后原样转绿

- **现象**：同一代码同一站点，两次失败（"performing click action" 卡 30s）后第三次原样通过。
- **影响**：无代码改动；判为机器瞬态抖动（探针在失败窗口内同路径即时通过）。
- **位置**：`tests/browser_stage30.py` 首页 chip 点击段。
- **建议**：留观察项；若再出现，先查同机是否有其他重活进程抢资源。

## 7. `.gitignore` 的 scratch 规则保留但要求用后即删

- **现象**：`_*.py/_*.txt/_*.png` 规则曾让根目录攒了 74 个调试残留（已清）。
- **影响**：规则本身有用（台架临时探针），但容易被当成垃圾桶。
- **位置**：`.gitignore` 15-19 行。
- **建议**：规则保留；以后探针用完立刻删，回归提交前 `git status` 确认根目录无 `_` 前缀文件。
