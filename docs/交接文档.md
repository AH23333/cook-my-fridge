# 交接文档（断点续作手册）

> 目的：任何时候中断，新会话读完本文件 + `实施进度.md` 即可无缝接手。

## 1. 项目是什么

CookMyFridge（冰箱开饭）：用户点选冰箱食材 → 数据集检索（Cook Now / Almost There）+ AI 创意（AI Wildcard），产物为可直接托管的静态站点。完整背景见 `项目产品定位.md`。

## 2. 环境与关键路径

- Python 3.13（运行时仅用标准库；测试用 pytest）。
- **本机解释器坑**：WorkBuddy 会话自带的 `python`（`~/.workbuddy/binaries/python/versions/3.13.12/python.exe`）**没有装 pytest**，`python -m pytest` 会报 `No module named pytest`。测试/审计/构建统一用 `D:\Python\python.exe`（Git Bash 里是 `/d/Python/python.exe`，pytest 9.1.1）；Node v22 跑一致性 harness；Python `playwright`、`Pillow`、`opencv-python`、`zxing-cpp` 已装，可做真实浏览器实测与二维码解码回归（后两者缺失时 QR 解码 pytest 会自动跳过）。
- git：`C:\Program Files\Git\cmd\git.exe`（PowerShell 下不在 PATH，命令需用绝对路径；Git Bash 里可直接用 `git`，但 `cd` 只在单条命令内有效）。
- GLM 密钥外部 .env：`D:\Py\PyCharmProjects\Langchain\lc-course\.env`
  - 代码通过 `config.zhipu_settings()` 读取，密钥不入库。
  - 可用环境变量 `COOKMYFRIDGE_ENV_FILE` 覆盖 .env 路径。
- 模型：`glm-4-flash`（OpenAI 兼容 `/chat/completions`）。

## 3. 目录地图

| 路径 | 用途 |
|---|---|
| `src/cookmyfridge/` | 领域模型、目录、营养表、归一化、校验、LLM、检索、构建 |
| `src/cookmyfridge/nutrition.py` | 每 100 g 营养参考值、家常单位换算与完整性校验（导出到 catalog.json） |
| `tests/` | pytest 全量测试（conftest 自动注入 src 路径） |
| `tests/consistency/` | Node 无头 harness（纯逻辑 + DOM/Canvas 渲染回归）；`test_reference_chain.py` 锁住 9 页脚本引用链；`test_qr_consistency.py` 用 ZXing 真实解码 QR 矩阵 |
| `web/js/balance.js` | 营养均衡评分、建议搭配、评分卡片与整份菜单摘要 |
| `web/js/qrcode.js` | 自研 QR 编码器（字节模式 / EC-M / **v1–v40** / RS / 8 掩码），Canvas 绘制；同步二维码靠高版本才能装下 |
| `data/curated/` | 人工/AI 菜谱 JSONL |
| `data/catalog/` | 构建导出的食材目录 JSON |
| `data/raw/` | 外部原始数据（如有） |
| `web/` | 静态站点源码（HTML/CSS/JS） |
| `site/` | 构建产物（可直接托管） |
| `docs/` | 产品、进度、踩坑、交接、架构等文档 |

## 4. 常用命令

```powershell
cd "D:\Visual Studio Code\Something\CookMyFridge"

# 测试（全量 131 通过 + 1 个需 RUN_LIVE=1 的真实 API 用例；一致性 harness 依赖 Node，QR 解码需 zxing-cpp 或 OpenCV）
& "D:\Python\python.exe" -m pytest tests -q

# 离线完整性审计（不联网，发现问题时退出码为 1）
& "D:\Python\python.exe" run.py audit

# 公开数据集导入（不捆绑第三方数据；--dry-run 只报告不落盘）
python run.py import --source data/raw/sample_public.jsonl --dataset "示例" --license "CC BY 4.0" --dry-run
python run.py import --source path/to/recipes.csv --dataset "某数据集" --license "ODC-BY"

# 为新增菜谱补齐缺失的变体/主意（只补不覆盖 AI 缓存，规则卡片标注非 AI）
python run.py enrich

# 数据与 AI 管线（run.py 统一入口，需联网调 GLM）
python run.py data            # 从策展规格生成 base_recipes.jsonl
python run.py wildcards       # AI Wildcard 离线批处理（可断点续跑）
python run.py blindboxes      # 冰箱盲盒
python run.py ideas           # 每道菜“数据集里没有的三个主意”
python run.py variants        # 变体；可 --kinds lazy 限定类型
python run.py repair          # 修复单字 safety_notes + 变体标题补后缀
python run.py prune-failures  # 对账并移除已恢复的失败记录
python run.py build           # 导出静态站点到 site/

# 本地预览（在 site 目录起服务器，浏览器实测；换新端口规避缓存）
cd site; python -m http.server 8768

# git（PowerShell 用绝对路径）
& "C:\Program Files\Git\cmd\git.exe" -C "D:\Visual Studio Code\Something\CookMyFridge" status
```

## 6. 工作纪律（用户明确要求）

1. 小步提交，每个可工作的增量即 commit，按关注点拆分（feat / test / build / docs）。
2. 深度测试，交付前跑全量 pytest + audit + build。
3. 每次踩坑写入 `踩坑记录.md`，进度写入 `实施进度.md`，断点更新本文件。
4. AI 内容必须结构化校验 + 明确 AI 标识 + 安全提示。
5. 用户未插话即默许继续开发与合理拓展。
6. 新增前端全局脚本必须同步引用链与预缓存，且交付前用真实浏览器点一遍并看截图（单测全绿也可能有 `[object Object]` 这类渲染错误）。
