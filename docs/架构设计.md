# 架构设计与数据字典

> 本文描述 CookMyFridge 的分层架构、构建期/运行期数据流、核心算法与导出 JSON 的字段字典。

## 1. 设计目标与约束

- 纯静态交付：站点可托管 GitHub Pages / Cloudflare Pages，无后端、无实时 API 依赖。
- 运行时零第三方依赖：Python 侧只用标准库；前端只用原生 HTML/CSS/JS。
- AI 内容离线批处理并强校验，密钥不入库。
- 数据预构建：所有检索在浏览器本地完成，AI 结果以静态 JSON 缓存。

## 2. 分层架构

```
┌────────────────────────── 构建期（离线，Python）──────────────────────────┐
│ 策展规格 curated_data*.py ──► dataset ──► 校验 ──► base_recipes.jsonl     │
│ catalog_data（单一事实源）──► catalog/catalog 读侧 API                    │
│ GLM API ──► llm ──► ai（白名单+校验+重试）──► batch ──► ai_cache/*.json   │
│ build：汇总 catalog/recipes/vocab/ai 缓存 + 复制 web 资产 ──► site/       │
└──────────────────────────────────────────────────────────────────────────┘
                                   │  site/ 静态产物
                                   ▼
┌────────────────────────── 运行期（浏览器，原生 JS）───────────────────────┐
│ store 预加载 JSON ──► catalog 初始化 ──► search 本地检索 ──► ui 渲染     │
│ 6 页面 + localStorage（冰箱/历史/反馈/偏好/计划/收藏）                  │
└──────────────────────────────────────────────────────────────────────────┘
```

### 模块职责（src/cookmyfridge）

| 模块 | 职责 |
|---|---|
| `config.py` | 路径常量、外部 .env 加载（密钥不入库） |
| `models.py` | Recipe/IngredientUse dataclass、受控词表、方法/标签别名 |
| `catalog_data.py` | 食材目录单一事实源（canonical、emoji、同义词、过敏原）、家常调料、替代表 |
| `catalog.py` | 带缓存的读侧 API（集合、映射、替代、分类、过敏原） |
| `normalize.py` | 脏食材名归一化（全角/括号/用量/多别名） |
| `validate.py` | 结构 + 白名单校验、词表快照 |
| `dataset.py` | 策展规格 → Recipe，派生过敏原与方法安全提示，JSONL 读写 |
| `llm.py` | GLM 客户端：围栏剥离、容错解析、退避重试 |
| `ai.py` | AI 引擎：wildcard/blindbox/variant/ideas 全闭环 |
| `batch.py` | 断点续跑的离线批处理、缓存修复、失败记录对账 |
| `build.py` | 导出静态数据分片并复制 web 资产 |
| `audit.py` | 离线完整性审计（标题/白名单/重复/键指向/单字提示） |

## 3. 核心算法

### 3.1 检索与三桶分类

- 家常调料（`PANTRY_STAPLES`：盐、食用油、酱油、醋、糖、淀粉、香辛料等）不计缺失。
- 对每道菜统计非调料、未命中的必需食材数 `missing`：
  - `missing = 0` → **Cook Now**
  - `1 ≤ missing ≤ 3` → **Almost There**（挂替代建议）
  - `missing > 3` → out_of_reach（不展示）
- 排序键：缺失数升 → 匹配数降 → 时间升 → 难度 → id。
- 方法/标签经别名归一（拌→凉拌、焖/烧→炖、快手菜→快手等）。

### 3.2 AI 闭环

调用 GLM → 围栏剥离/容错解析 → 食材 `normalize_strict` 白名单强校验 → `validate_recipe` → 失败带反馈重试。强制 AI 免责声明、过敏原与方法安全提示；列表字段先 `_as_list` 再迭代，防止字符串被逐字符拆分。

### 3.3 批处理可靠性

- 每个成功项立即落盘，重跑自动跳过（断点续跑）。
- 单项失败写 `failures.json`，不中断整批；429/5xx 指数退避。

## 4. 数据字典（site/data 导出 JSON）

### 4.1 `catalog.json`

| 字段 | 类型 | 说明 |
|---|---|---|
| `ingredients` | array | 食材条目，见下 |
| `substitutions` | object | canonical → 替代列表 |
| `pantry_staples` | array[string] | 家常调料，不计缺失 |
| `method_aliases` | object | 方法别名 → 标准方法 |
| `tag_aliases` | object | 标签别名 → 标准标签 |

食材条目：

| 字段 | 类型 | 说明 |
|---|---|---|
| `canonical` | string | 标准名（唯一） |
| `category` | string | 8 分类之一 |
| `emoji` | string | 展示图标 |
| `synonyms` | array[string] | 同义词，全局不得一对多 |
| `allergens` | array[string] | 该食材关联过敏原 |

### 4.2 `recipes.json`（Recipe 数组）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 菜谱唯一 id（如 r001；AI 为 ai-wild-xxx） |
| `title` | string | 菜名 |
| `ingredients` | array | IngredientUse，见下 |
| `steps` | array[string] | 做法步骤 |
| `methods` | array[string] | 12 种受控烹饪方法 |
| `cuisine` | string | 菜系/来源分类 |
| `time_minutes` | integer | 预计耗时（分钟） |
| `difficulty` | string | 简单/中等/较难 |
| `cookware` | array[string] | 所需厨具 |
| `tags` | array[string] | 受控标签 |
| `allergens` | array[string] | 派生过敏原 |
| `safety_notes` | array[string] | 安全提示，首条为 AI 免责声明（AI 菜） |
| `source` | string | 来源 |
| `license` | string | 许可证 |
| `is_ai_generated` | boolean | 是否 AI 生成 |

IngredientUse：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 原始写法 |
| `canonical` | string | 标准食材名 |
| `amount` | string | 自由文本用量 |
| `optional` | boolean | 是否可选（可选不计缺失） |

### 4.3 `vocab.json`

受控词表快照：`categories`（8）、`methods`（12）、`difficulties`（3）、`tags`（17）。
注意难度字段是复数 `difficulties`，方法/标签读取前需核对键名。

### 4.4 `data/ai/*.json`

均为数组，构建时在每条前注入 `key`（工作负载键）：

| 文件 | 元素 | 说明 |
|---|---|---|
| `wildcards.json` | Recipe + `key` | AI 创意菜 |
| `blindboxes.json` | Recipe + `key` | 冰箱盲盒 |
| `variants.json` | Recipe + `key` | 菜谱 7 种变体（lazy/lowcal/airfryer/substitute/method/leftover/fusion） |
| `ideas.json` | `{key, ideas:[3]}` | 每道菜“数据集里没有的三个主意” |

## 5. 前端运行期

- 全局命名空间 `window.CMF`，非 ES module，兼容 `file://` 与静态托管。
- 脚本分层：store（加载/存储）、catalog（查询/归一）、search（检索）、ui（共享渲染/启动）、page-*（各页面）。
- localStorage 键：`cmf.fridge`、`cmf.history`、`cmf.feedback`、`cmf.prefs`、`cmf.plan`、`cmf.favorites`。
- 页面间通过 URL 参数 `i`（逗号分隔、URL 编码）传递食材；wildcard 用 `key`，盲盒用 `blind=1`。

## 6. 部署

把 `site/` 整体推到静态托管即可，无需构建命令。GitHub Pages 选对应分支目录；CF Pages/Netlify 发布目录设为 `site`。
