# CookMyFridge · 冰箱开饭

> **Don’t order. CookMyFridge.** 别点外卖，让冰箱开饭。

点选冰箱里的食材，**数据集引擎**负责靠谱的菜谱，**AI 引擎**负责没见过的创意。所有菜谱数据预构建、AI 结果离线批处理，最终产出一个可直接托管在 GitHub Pages / Cloudflare Pages 的**纯静态网站**——无需后端、无需登录。核心功能完全离线；另有可选的免费在线信息源（Open-Meteo 天气、Open Food Facts 包装食品营养）与浏览器原生能力（语音输入、摄像头扫码）做增强，断网时自动降级为手动/离线模式，不影响主流程。

## 特性

- **双引擎**
  - 数据集检索：Cook Now（严格 0 缺失）/ Almost There（1–3 缺失，挂替代建议）。
  - AI 创意：Wildcard 创意菜、冰箱盲盒、菜谱详情页 7 种 AI 变体、“数据集里没有的三个主意”。
- **九个页面**：首页（食材墙/点选/随机开一局）、结果页（三桶 + 实时筛选 + 解锁面板）、菜谱详情、AI 创意菜、我的冰箱、全部菜谱浏览、一周菜单、统计、关于。
- **多周双餐菜单**：依据冰箱、口味、过敏原和饮食偏好自动生成 1–4 周、每天午餐 + 晚餐（14–56 道）不重样的菜，支持单餐换菜、整份重生成、每日热量估算、跨周归并的采购清单（标注第几周需要），以及导出 `.ics` 日历（午餐 12:00 / 晚餐 18:00，按北京时间）。
- **日历订阅**：菜单页一键开启 `/calendar.ics` 订阅，Service Worker 用 Cache Storage 提供虚拟端点，菜单每次改动自动同步；可复制 https 与 webcal 链接添加到日历 App。需站点部署在公网 HTTPS 且浏览器已激活 SW。
- **个性化与安全**：口味偏好（素食/低卡/减脂/快手）持久化；过敏原档案在结果页对危险菜谱警示并可一键隐藏；饮食偏好（无麸质 / 生酮低碳水 / 纯素）在结果页、全部菜谱浏览和一周菜单统一生效，判定规则保守且 fail-closed。
- **开饭计划**：把想做的菜加入计划，冰箱页自动聚合去重购物清单，可逐项勾选划线。
- **收藏菜谱**：在卡片或详情页一键收藏，冰箱页集中查看，支持移除。
- **食材百科**：菜谱详情点击食材名，弹窗展示分类、同义词、过敏原、常见替代和用到它的菜谱。
- **食材经典搭配**：百科弹窗基于全部菜谱的真实共现统计，给出最常一起出现的 6 个搭档（自动剔除盐、食用油等常备调料），点击芯片可继续跳转查看；纯离线计算，无硬编码搭配。
- **随机看看**：首页一键从全数据集随机打开一道菜，没食材也能找灵感。
- **全部菜谱浏览**：独立浏览页，按做法/标签/时间/关键字筛选，卡片可直接收藏或加入计划。
- **相似菜谱**：详情页按共享食材数推荐其他菜谱，顺手发现可做的新菜。
- **厨房计时器**：烹饪模式内置倒计时，1/3/5/10 分钟预设，时间到声音提醒，翻页不中断。
- **备份与恢复**：冰箱页可导出全部本地数据为 JSON，换设备/浏览器时导入恢复。
- **帮我决定**：选择困难时一键随机挑一道，优先零缺失菜。
- **清冰箱方案**：贪心集合覆盖算法，自动组合最多 4 道菜，最大化消耗现有食材、减少浪费，并列出覆盖率与需补采购。
- **临期食材**：点 ⏰ 标记快过期，清冰箱方案对临期食材加权（3 倍），优先消耗。
- **自然语言输入**：一句话描述“我有西红柿、鸡胸肉和小葱”，离线最长匹配自动识别并加入冰箱，无需联网。
- **营养估算**：详情页展示每份热量、蛋白质、脂肪、碳水与三大营养素供能占比，随份量缩放联动；基于 261 个食材的每 100 克近似成分表 + 家常单位换算（把/颗/勺/碗等），炒菜省略的常备食用油按 10 g 计入并明确标注。菜谱浏览可按热量上限筛选，一周菜单显示每日两餐合计热量。**为估算值，不替代食品标签或专业营养建议。**
- **个性化营养目标**：按性别 / 年龄 / 身高体重 / 运动量 / 目标（减脂·维持·增肌）与全家人数、每日餐数，用 Mifflin-St Jeor 公式算出每日与每餐的热量及三大营养素目标；详情页显示本菜占目标的比例，菜单日卡显示达成提示，均衡评分在启用目标时改用个人供能比。不填目标时保持默认 AMDR 评分不变。**启发式参考，非临床营养建议。**
- **营养均衡评分**：按成人三大营养素供能比（蛋白 10–20% / 脂肪 20–30% / 碳水 50–65%）、蛋白密度与热量充足度给出可解释的 0–100 分，附具体建议与可搭配的真实食材；详情页展示单菜评分，菜单页展示每日徽章、整份菜单摘要与「优化较弱的几天」（只替换得分最低的至多 1/3 天中的一餐，保留其余手选）。**启发式搭配提示，非临床营养建议。**
- **定性营养标签**：高蛋白/高纤维/低脂/低碳水/优质碳水等徽章仍在详情页与浏览页可用。
- **统计与口味画像**：统计页用纯 CSS 条形图展示个人历史/收藏/计划、冰箱分类和口味画像，以及数据集做法/标签/分类分布，全部动态计算。
- **烹饪模式**：详情页一键进入全屏分步模式，大字号、上一步/下一步，并尝试用唤醒锁保持屏幕常亮。
- **份量缩放**：0.5×–3× 一键调整食材用量，数字用量自动换算，非数字用量保持不变。
- **菜谱分享图 + 二维码**：详情页一键用 Canvas 生成 800×1200 的分享卡片（菜名、食材、营养估算、免责声明、指向菜谱页的二维码），可下载 PNG、复制菜谱文字或调用系统分享；二维码由项目自带的 QR 编码器（字节模式 / EC-M / **v1–v40** / GF(256) RS / 8 掩码）离线绘制，无外部库与网络请求，图片完全在本地生成。分享链接带 UTM 参数便于站点统计，本地还记录各渠道分享次数。
- **按周购物清单**：1–4 周菜单的采购清单按周与分类分组，跨周重复食材分别列出，可逐项勾选（状态随菜单持久化），一键导出带 BOM 的 CSV 或可勾选的 TXT。
- **多设备同步（无后端）**：冰箱页把冰箱、偏好、收藏、菜单与营养目标打包成同步码 / 同步文件 / 二维码；在另一台设备粘贴、导入或扫码打开 `#sync=` / `#s=` 链接即可合并或覆盖。同步码用短键 + 同步 LZ77 + base64url 压缩，二维码按数据量自动选用 v1–v40，Canvas 按模块数放大以保证可扫。全部在本机完成，不需要账号与服务器；菜单（最多 56 餐）请用同步码或文件，二维码只带精简快照。
- **节气与当季食材**：首页按当天日期显示当前节气（二十四节气离线表）与本月当季食材芯片，点一下加入冰箱；浏览页可一键「只看本月当季」；食材百科弹窗对当季食材加徽章。纯离线计算。
- **天气开饭建议**：首页接 Open-Meteo 免费天气 API（无 Key、CORS），按温度与降水把天气分成炎热/舒适/凉爽/寒冷/雨/雪等档，从真实数据集推荐对应做法的菜；按预设城市查询，不请求定位权限；断网时可手动选天气，建议仍来自本地数据集。天气缓存 30 分钟，只存本机。
- **语音食材输入**：首页麦克风按钮用浏览器原生 Web Speech API 把一句话转成文字再走离线识别加入冰箱；不支持的浏览器自动隐藏按钮，未授权麦克风时给出提示而非报错。
- **开饭打卡与成就**：菜谱详情页可「我做过这道菜」打卡，记录日期、份量、评分（1–5 星）与笔记，并快照当时的每份估算热量与整菜成本；统计页展示累计/连击/平均评分、9 枚厨房成就徽章、最高评分菜与近 7 天开饭趋势，以及「省下外卖钱」估算。打卡数据随备份/同步一起迁移。
- **食材成本估算**：详情页与打卡按 226 个 explicit 单价 + 类别兜底（元/500g）估算整道菜成本，明确标注「估算、非实时菜价」；统计页用外卖均价对比算省下的钱。
- **包装食品营养查询**：冰箱页接 Open Food Facts 开放数据库（ODbL、需联网、界面署名），按名称搜索或条码（8–14 位）查询每 100g 热量/蛋白/脂肪/碳水与 Nutri-Score；支持摄像头扫码（原生 BarcodeDetector，特性检测）。结果不并入菜谱目录，离线时给出明确提示。
- **厨房换算工具**：冰箱页离线换算勺/杯/碗 ↔ ml ↔ 克（约 35 种食材密度）、烤箱 °C ↔ °F，并附 8 条常见烘焙替代表；未知食材不瞎猜密度，全部标注近似。
- **储存百科**：食材百科弹窗新增储存行（93 条 explicit 保存法 + 冷藏/冷冻天数，其余按类别兜底），帮你在买之前就知道怎么放。
- **打印友好**：打印菜谱时自动隐藏导航与按钮，只保留干净的食材与步骤。
- **PWA 离线**：可安装、可离线；构建时自动版本化 service worker 缓存，避免老用户拿到旧内容，HTML/CSS/JS/数据均在首次安装时预缓存。
- **灵活添加**：食材墙点选，也可在搜索框输入名称（含同义词）回车直接添加。
- **纯静态**：原生 HTML/CSS/JS，无框架、无打包步骤，`file://` 与静态托管都能跑（SW 需 http/https）。
- **数据治理**：AI 输出必须通过固定字段校验 + 食材白名单，强制 AI 标识、过敏原与安全提示；失败自动带反馈重试。
- **隐私优先**：冰箱、历史、反馈、偏好只存在浏览器 localStorage，不建账号、不收集数据。

|---|---|

| 食材目录 | 261 |
| AI Wildcard | 20 |

公开菜谱数据可通过 `run.py import` 从 JSONL / CSV 导入到**独立分片** `data/curated/imported_recipes.jsonl`，构建时与策展语料合并；仓库本身不捆绑第三方数据，导入需显式声明来源与许可证。

## 快速开始

环境要求：Python 3.10+（运行时仅用标准库；测试需 `pip install pytest`）。

```powershell
# 1. 跑测试
python -m pytest tests -q

# 2. 构建静态站点
python run.py build

# 3. 本地预览
cd site
python -m http.server 8766
# 浏览器打开 http://127.0.0.1:8766/
```

## 配置 GLM API

AI 批处理需要智谱 GLM 的 API Key。代码默认从外部 `.env` 读取，**密钥不会入库**：

- 默认读取路径可用环境变量 `COOKMYFRIDGE_ENV_FILE` 指向你的 `.env`。
- `.env` 需包含：
  ```
  ZHIPU_API_KEY=你的key
  ZHIPU_BASE_URL=https://open.bigmodel.cn/api/paas/v4
  ```
- 使用模型 `glm-4-flash`（OpenAI 兼容 `/chat/completions`）。

数据与 AI 管线命令：

```powershell
python run.py data         # 从策展规格生成基础菜谱
python run.py wildcards    # AI Wildcard 批处理（断点续跑）
python run.py blindboxes   # 冰箱盲盒
python run.py ideas        # 每道菜“三个主意”
python run.py variants     # AI 变体，可 --kinds lazy 限定
python run.py repair       # 修复单字安全提示与变体标题
python run.py prune-failures  # 移除已恢复的失败记录
python run.py import --source <file.jsonl|.csv> --dataset "名称" --license "许可证" [--dry-run]
python run.py enrich       # 只补缺失的变体/主意（不覆盖 AI 缓存，规则卡片标注非 AI）
python run.py audit        # 离线完整性审计（不联网，发现问题退出码 1）
python run.py build        # 导出静态站点
```

批处理可随时中断，已成功的条目立即落盘，重跑会自动跳过。单项失败写入 `failures.json`，不中断整批。

## 部署

将 `site/` 目录整体推送到任意静态托管即可：

- **GitHub Pages**：把 `site/` 内容放到仓库根（或 `/docs`），在 Settings → Pages 选择对应分支。
- **Cloudflare Pages / Netlify / Vercel**：构建命令留空，发布目录设为 `site`。

## 数据与 AI 治理

- 食材目录是单一事实源，含同义词、过敏原、替代表、家常调料集合。
- AI 生成的食材必须命中目录白名单，未通过校验的结果不会展示。
- 所有 AI 内容标注「AI 创意菜，未经过人工实测」，并附过敏原与方法安全提示。
- 常见过敏原（鸡蛋、牛奶、花生、大豆、麸质、鱼、甲壳类等）均有标注，但不能替代食品包装标签与专业医疗建议。

## 拓展开发

- **加食材**：在 `src/cookmyfridge/catalog_data.py` 增加条目（emoji、分类、同义词、过敏原）；营养估算会自动用类别默认值兜底，想更准就在 `src/cookmyfridge/nutrition.py` 的 `NUTRIENTS_PER_100G` / `INGREDIENT_UNITS` 补精确值。
- **加菜谱**：在 `curated_data*.py` 以紧凑规格追加，`python run.py data` 重新生成。
- **加 AI 工作负载**：在 `batch.py` 的组合列表追加，重跑对应批处理。
- 每次改动后跑 `python -m pytest tests -q`、`python run.py audit`，并用 `python run.py build` 重新导出。QR 解码回归需要 `zxing-cpp`（或 OpenCV）+ Pillow，缺失时 pytest 会自动跳过。
- **加前端全局脚本**：必须同步 9 个 HTML 引入（顺序 `nutrition → goals → balance → diets → seasonal → prices → journal → 页面专属 → pairings → qrcode → share → sync → ui`，共 31 个 JS）、CSS 样式、调用方兜底、`sw.js` 预缓存清单与无头回归测试，缺一会造成整页功能失效（见 `docs/踩坑记录.md` 第 27、34、45 条）；`tests/test_reference_chain.py` 会锁住引用链。
- **免费在线信息源**：天气用 Open-Meteo（无 Key、CORS），包装食品营养用 Open Food Facts（ODbL，界面必须署名）。两者都只在用户主动触发时请求，失败/断网要降级为手动或离线提示，不得让主流程抛错；瞬时缓存（天气、最近搜索）放 localStorage 但**不进**同步 KEYS，避免把设备临时状态带到别的设备。在线查询会把所选城市或搜索词/条码发往对应服务；浏览器语音识别可能使用浏览器供应商的在线服务，不保证离线。新增外部源前先确认免费额度、CORS 与许可证署名要求。
- **二维码容量**：`qrcode.js` 支持 EC-M v1–v40（最大 2331 字节）。v1–v10 的 EC-M 块表与 v11–v40 的表、对齐图案坐标都用 `segno` 常量表对过账；改动编码器必须用 ZXing 对**真实浏览器生成的 PNG** 解码验证（踩坑 39–41、46）。同步链接真实数据量约 489 字节落在 v17，渲染 Canvas 按 `(modules+8)*3` 放大，不要改回固定 220px。
- **公开数据集**：导入结果只写 `data/curated/imported_recipes.jsonl`，不要写进 `base_recipes.jsonl`（会被 `run.py data` 重建清空）；导入前先 `--dry-run` 看未知食材待审报告，并确认数据源许可证允许再分发。
- **构建偶发失败**：`run.py build` 若报 `safe-delete / trash operation` 失败，重跑一次并用哈希核对 `web/ ↔ site/` 全部资产（踩坑 50）。
- **日历订阅**：`calendar.ics` 不是真实文件，`sw.js` 从 `cmf-calendar-v1` 缓存读取页面写入的 ICS；修改订阅逻辑时务必同时检查 SW 的 `activate` 白名单，否则缓存会被旧版本清理掉。
